# System Design Articles

Twelve system design reads from [Franco Fernando's newsletter](https://newsletter.francofernando.com) ([original LinkedIn post](https://www.linkedin.com/posts/fernando-franco-4696708_if-youre-a-software-engineer-who-wants-to-activity-7358878397155926016-3-WK)).

1. [Designing a URL shortener](https://newsletter.francofernando.com/p/designing-a-url-shortener) - a popular interview question, from simple concept to scalable system.
2. [Database categories](https://newsletter.francofernando.com/p/database-categories) - relational, NoSQL, time-series and NewSQL.
3. [How not to fail a system design interview](https://newsletter.francofernando.com/p/how-not-to-fail-a-system-design-interview) - common mistakes and how to avoid them.
4. [The Shopify checkout architecture](https://newsletter.francofernando.com/p/the-shopify-checkout-architecture) - sandboxing for secure checkout pages.
5. [Observability](https://newsletter.francofernando.com/p/observability) - the three pillars and why Booking uses a different approach.
6. [Back-of-the-envelope estimation](https://newsletter.francofernando.com/p/back-of-the-envelope) - measure capacity and performance requirements to choose a design.
7. [Availability](https://newsletter.francofernando.com/p/availability) - design highly available systems and measure availability.
8. [Redis](https://newsletter.francofernando.com/p/redis) - architecture, data types, persistence model and use cases.
9. [The definitive guide to load balancers](https://newsletter.francofernando.com/p/the-definitive-guide-to-load-balancers) - load balancers in distributed systems.
10. [Database sharding case study: PostgreSQL](https://newsletter.francofernando.com/p/database-sharding-case-study-postgresql) - how Notion sharded its monolithic Postgres.
11. [How Quora scaled MySQL](https://newsletter.francofernando.com/p/how-quora-scaled-mysql) - supporting 100k+ queries per second.
12. [A comprehensive guide to database sharding](https://newsletter.francofernando.com/p/a-comprehensive-guide-to-database) - make a database more scalable, faster and available.
